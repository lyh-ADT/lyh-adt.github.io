# 待办记录 · Todo Files

一个完全本地运行的待办记录页面。使用浏览器 [File System Access API](https://developer.mozilla.org/zh-CN/docs/Web/API/File_System_Access_API) 直接读写你选择的文件夹：

- **文件夹就是分类**：一级子文件夹对应一个分类。
- **一个文件就是一条待办**：文件夹里的每个 `.md` / `.markdown` / `.mdown` / `.mkd` / `.txt` 文件都会显示为一条待办。
- **文件内容就是待办详情**：frontmatter 保存标题、状态、优先级、截止日期等元数据，正文就是详情。
- **数据不上传**：没有后端、没有账号，文件始终留在本地。

## 使用

1. 用桌面版 Chrome / Edge 等 Chromium 浏览器打开页面。
2. 点击「选择文件夹」，选择一个本地文件夹（建议新建一个空的待办文件夹）。
3. 左侧新建分类，或在列表上方直接输入待办标题并回车。
4. 编辑标题、详情、分类、优先级和截止日期，修改会自动保存。
5. 下次打开页面时，浏览器会尝试自动恢复上次选择的文件夹；如果权限失效，点击「重新连接」即可。

> 浏览器只会把文件夹句柄保存在 IndexedDB 中，不会复制或上传任何待办内容。

## 文件夹结构

```text
我的一天/
├── 工作/
│   ├── 准备周会材料.md
│   └── 回复设计评审意见.md
├── 生活/
│   └── 买牛奶.txt
└── 未分类的待办.md
```

分类可以随时在页面里新建、重命名或删除。删除非空分类时，其中的待办会先移动到「未分类」，再删除空文件夹；如果分类里还有非待办文件（例如附件、图片），文件夹会被保留，避免误删。

## 文件格式

新建或保存后的待办文件类似这样：

```markdown
---
title: "准备周会材料"
done: false
priority: "high"
due: "2026-10-30"
created: "2026-10-20T01:00:00.000Z"
updated: "2026-10-20T04:30:00.000Z"
---

## 准备步骤

- [ ] 收集各小组进度
- [x] 预定会议室

负责人：林
```

- `title`：待办标题，同时用于生成文件名。
- `done`：是否完成。
- `priority`：`low` / `normal` / `high`。
- `due`：截止日期，`YYYY-MM-DD`，可为空。
- `created` / `updated`：ISO 时间。
- frontmatter 下方的内容原样作为详情，支持 Markdown 预览。

### 兼容已有文件

没有 frontmatter 的 Markdown 也能读取：

- 如果第一行是 `# 标题`，标题取自这一行，其余内容作为详情。
- 否则标题取自文件名，整个文件内容作为详情。
- 第一次在页面中编辑并保存后，文件会补上 frontmatter，文件名也可能根据标题更新。

隐藏文件/文件夹（以 `.` 开头）会被忽略；不支持的文件类型（例如 `.pdf`、图片）不会被读取或修改。

## 本地开发

```bash
cd todo-list
npm install
npm run dev      # http://localhost:5175/todo-list/
npm test         # 文件格式和文件系统逻辑的单元测试
npm run build    # 输出到 ../docs/todo-list
```

构建产物提交在仓库的 `docs/todo-list`，与其他页面一起通过 GitHub Pages 发布。

## 浏览器支持

File System Access API 目前主要由桌面版 Chromium 浏览器支持（Chrome、Edge 等）。Firefox、Safari 和不支持该 API 的浏览器会显示提示，无法选择文件夹。

## 说明

- 页面不会自动创建或修改分类之外的任何文件。
- 如果同时在文件管理器或其他编辑器中修改文件，点击右上角刷新按钮可重新读取；外部修改可能与页面内未保存的内容冲突。
